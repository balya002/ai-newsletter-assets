Agents were a major part of July’s AI updates. The practical difference is that a team can save a repeatable process instead of rewriting the same instructions every time the work comes back.
A regular prompt is still the better choice for a one-time request. An agent becomes useful when the same task happens repeatedly, relies on the same types of information, and needs to follow the same rules and output structure each time.
What an agent adds
One-time prompt
The user provides the task, context, rules, source material, and desired format for that request.
Agent
The recurring instructions, approved knowledge, decision rules, and output requirements are already built into the tool.
That does not make the work automatic or error-proof. It removes the need to rebuild the same process from scratch and gives the user a more consistent starting point.
A narrow job usually produces a better agent
“Help with campaign management” is too broad. A stronger agent owns one defined job with a clear beginning and end.
  • Turn the current pacing and pipeline inputs into the weekly team report
  • Check a VAST tag against one approved requirements document
  • Match two delivery reports and calculate the required buffer
The agent is only as clear as the workflow behind it
Before an agent is built, the process needs to be written down. That includes the required inputs, source of truth, order of steps, calculations or rules, expected output, and the situations that require human review.
If the team cannot agree on how the work should be completed manually, the agent will not fix that ambiguity. It will reproduce it inconsistently.
What changed in July
Microsoft added a more formal way for organizations to review and share agents built in Microsoft 365 Copilot. Google also expanded support for longer-running agent tasks and connections to outside tools. Both updates point in the same direction: agents are being built for ongoing work, not just isolated chat responses.

A practical guide to turning one repeatable workflow into a focused Microsoft 365 Copilot agent and writing the permanent instructions in a consistent format.
Build the workflow before you build the agent
Start with one process that can be explained from beginning to end. The agent should have a specific job, a defined source of truth, clear rules, and an output that can be reviewed.
Step 1: Choose one repeatable outcome
Use work that follows the same general process each time, such as preparing a recurring report, checking an item against approved rules, or reconciling two reports.
Step 2: Define the inputs and source of truth
List what the user must provide and which connected files, SharePoint pages, or approved reference materials the agent is allowed to use.
Step 3: Create the agent and open Configure
In Microsoft 365 Copilot, select New agent. Use the Configure tab to set the name, description, permanent instructions, knowledge sources, capabilities, and starter prompts.
Step 4: Write the permanent instructions
Use the instruction format below. Explain the purpose, required behavior, skills, inputs, order of operations, output, and restrictions.
Step 5: Add only the knowledge and capabilities it needs
More access does not automatically improve the result. Connect only the approved sources and capabilities required for the workflow.
Step 6: Test the complete workflow
Test a normal case, a no-issue case, a missing-information case, and a conflicting-information case. Check the sources used, the decisions made, and the final format.
Step 7: Add starter prompts only after testing
Use only starter prompts that have been tested successfully with the final instructions and connected knowledge.
Step 8: Pilot before broad sharing
Test with a small group, collect examples of incorrect or confusing output, and update the instructions or knowledge source before wider use.

Reusable agent instruction format
Use these headings when writing the permanent instructions in the agent’s Configure tab.
# Purpose
Explain the single business outcome this agent is responsible for and who will use the result.

# General Guidelines
- State the tone, level of detail, and overall behavior expected from the agent.
- Identify the approved source of truth.
- Require the agent to preserve source names, dates, figures, and terminology when accuracy matters.
- Tell the agent not to guess when information is missing or conflicting.

# Skills
- List the specific tasks the agent must complete.
- Include only skills required for this workflow.
- Separate analysis, calculation, validation, formatting, and summarization when they follow different rules.

# Required Inputs
- List every file, field, link, selection, or user-provided detail required to begin.
- Explain which inputs are optional and when they are needed.
- Tell the agent what to do when a required input is missing.

# Step-by-Step Instructions
1. Explain how the agent should inspect and validate the inputs.
2. Explain the order in which the work should be completed.
3. Define the decision rules, calculations, matching logic, or compliance checks.
4. Explain how to handle duplicates, conflicts, missing information, or uncertain results.
5. Require a final check against all instructions before returning the result.

# Output Requirements
- Define the exact sections, columns, headings, or file format required.
- State what must be included and what should be omitted.
- Define how concise or detailed the output should be.
- Include an approved example only when it has been tested and should be followed exactly.

# Restrictions
- Do not invent missing facts, causes, conclusions, or next steps.
- Do not use unapproved sources.
- Do not change source values or names unless the instructions explicitly require a transformation.
- Stop and request human review when the result cannot be completed confidently.
Keep the headings consistent across agents. Customize the content beneath them for the specific workflow.

Shared company tool
Pacing & Pipeline Report Agent
This agent is designed to reduce the manual work behind the weekly pacing email. It organizes the current reporting into the established sections used by the team, while keeping live issues, ended campaigns, and upcoming launches separate.
Use it for
  • Weekly booked revenue and revenue-at-risk totals
  • Live revenue at risk, underpacing, and late lines
  • Recently ended campaigns and any under-delivery details
  • Upcoming campaigns, line items, planned start dates, and launch notes
How to use it
Open the agent and provide the current reporting and pipeline information requested in the experience. The agent will create the first draft of the weekly report using its built-in instructions and formatting.
Review before sending
Compare the revenue totals, percentages, campaign names, line-item names, dates, status categories, reasons, and next steps against the original source materials. The final email should still be reviewed by the account team.

Examples of Agents You Can Build
The following agents demonstrate how a defined review or reconciliation process can be turned into a reusable agent. They are not pod-wide approved tools and are still being tested.
VAST Tag Checker Agent Still being tested
This agent provides a faster first review of a VAST tag. It compares the pasted or uploaded XML against the approved requirements connected to the agent and focuses on issues that may prevent the tag from being accepted or served correctly.
Use it for
  • Checking vendors, domains, macros, media files, tracking, and XML elements against the approved requirements
  • Identifying the exact element or value connected to an issue
  • Separating actionable problems from normal serving behavior
  • Returning the relevant rule and the action required to resolve the issue
How to use it
Paste the complete VAST XML into the agent or upload it as an XML or text file. Include the intended platform or inventory when that detail changes which requirements apply.
Review before approval
Confirm the cited rule and inspect the exact XML value connected to each flag. While testing continues, share false positives, missed issues, or unclear explanations so the instructions can be improved.

Buffer Check Agent Still being tested
This agent compares Disney first-party delivery with the client’s external reporting. It currently works only with the MSTR "Standard Delivery by Creative by Day" report for Disney first-party data and should not be used with other MSTR report formats.
Use it for
  • Matching campaigns, line items, creatives, placements, and durations across the two reports
  • Comparing Disney first-party completions with the applicable external video-complete field
  • Calculating the discrepancy and recommended buffer using the established rounding rules
  • Flagging uncertain matches for manual review instead of forcing a result
How to use it
Upload the MSTR Standard Delivery report and the client’s external report. Make it clear which file is which when the filenames do not identify the source. Do not use a different MSTR export, since the agent’s field mapping and calculation logic are built for the Standard Delivery format.
Review before using the result
Confirm the external completion total, every match, slate calculations, negative discrepancies, and whole-number rounding. While testing continues, report extra rows, missing rows, incorrect matches, or calculations that need correction.
